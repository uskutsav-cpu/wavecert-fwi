# Prospective coordinate/cost engineering comparison

This AI-authored provisional software harness compares only native squared
slowness and standard physical velocity under the existing exact L-BFGS-B
engine. It is not the student's final question/design, independent confirmation,
method novelty, a certificate/FNO study, recovery evidence or completion of any
of the four scientific requirements. The eight cases have already been
inspected; repetitions and SEAM provider IDs do not create independent geology.

All 48 case/method/repetition entries are saved before project input reads.
Each adjacent pair uses seeded method order 2026110801. Every run really repeats
the three pinned input reads/hashes, fixed 24→49 refinement, initial smoothing,
all 24-block observations and common-start conversion inside the global clock.
No observation, factorization, field, gradient or optimizer history is shared
between policies. Shared imports/bootstrap are reported once, without fictional
per-run charges. Cold native/wrapper constructors, all rejection/cache work and
the engine's finish metadata remain paid.

Both arms compute `(v0, common_m, record) = start_from_slowness(requested_m)`.
The native arm starts from `common_m`; the velocity arm starts from `v0` and
must map to those identical native bytes. Requested/original, actual common,
velocity and observation hashes remain distinct. The actual first paid
checkpoint and velocity native-initial receipt are checked against that binding
after engine initialization; changed/clipped initial states fail closed.
Float64 roundtrip differences and actual bound hashes are retained, without
clipping, ULP search or borrowing the original initial receipt.

The engine budget is fixed at 7.5 seconds to reserve 0.5 seconds under an
8-second full API-return cap. The first engine clock reading returns the actual
pre-preparation start, and subsequent readings use the real clock. After the
engine returns, the API still validates the paid start, converts the returned
velocity into actual native m, hashes snapshots, validates/serializes output
provenance and refreshes costs. The caller timestamps the complete payload's
return. The reserve is not a guarantee and is never adjusted from outcomes.
Bounded per-run progress writes remain measured subsets; full growing status,
artifact compression and audits happen outside the API interval. No prefix or
progress time is added a second time.

All original engine settings are retained except the explicit 7.5-second
budget: maximum steps 200, maxcor 10, ftol 1e-12, gtol 1e-10 and the original
line-search/options. The numerical gtol acts in different coordinates; it is
not an equal physical stationarity tolerance. No coordinate-specific setting,
prior or target-stop choice is tuned. The old 0.5/0.25 objective ratios are
descriptive returned-final diagnostics only, with null event times when
unreached, failed, late or ineligible; eight seconds is never imputed.

Trajectory/checkpoint/final parameter fields carry explicit m/v tags. No old
m-only budget/quality helper consumes velocity. Saved vectors are requested and
common initial m, initial v/parameter, final parameter and actual final native
m. Intermediate vectors remain compact hashes, so full intermediate replay is
not claimed. Final conversion/hash/provenance costs are included before API
return; the later physical-velocity error is consistently `1/sqrt(actual_m)`
in both arms.

Only a fully returned, cost-complete, nonfailed paid state at or before eight
seconds, with terminal integrity/audit eligibility, receives primary quality
credit. There is no internal-checkpoint or unpaid-initial fallback credit.
Every planned row and late/failure status remains visible. After return, own
m/v errors and a fresh separately assembled sparse-Helmholtz audit evaluate the
common actual initial and final m. The independent audit rebuilds observations
and records its LU/RHS/residual checks and time separately. It shares
NumPy/SciPy/SuperLU and uses ordinary floating point, not a formal enclosure.
Neither its truth quantities nor errors enter policies or stopping.

Attempt/progress paths are persisted before work. Interrupts keep the full
denominator, current phase/wall and remaining unattempted rows. In-flight
counters are explicitly unknown/incomplete; after a returned-engine/output
failure, both earlier engine counts and a best-effort current policy snapshot
are retained separately. Returned parameters are preserved before post-return
integrity/audits. Source/input/disk failures stop without auto-resume, retries,
overwriting or changing the fixed reserve.

The default CLI only reports source/protocol hashes and 48 planned entries.
An actual run requires the explicit execution flag, both reviewed hashes, a
new OUTER output directory, fixed single-thread settings, root freeze/GO and
isolated timing CPU. Initial free-disk guard remains 256 MiB and per-run reserve
64 MiB. Current tests use only abstract clocks and synthetic arrays; they do
not load the project dataset or run trajectories/PDEs.
