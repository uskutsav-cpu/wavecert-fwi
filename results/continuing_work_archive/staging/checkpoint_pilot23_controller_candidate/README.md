This is a separately versioned, held controller for exactly twenty-three constant-medium checkpoint-pilot workers. It is not a 48-run optimizer registration or a 96-run continuation launcher. Its frozen plan contains saved history, explicit K2, explicit K4, then every combination of two physical-m directions, five fixed epsilon values and both signs. The full ordered plan, commands, output paths and unattempted states are recorded before any child starts. The original worker319, accounting1b, protocol08 and thirteen-file runtime pin map remain exact copies.

The controller defaults to metadata and starts nothing. This stage supplies no GO, installation script, numerical environment, workflow or job. The environment template intentionally cannot pass admission. Before any future native pilot, root and independent reviewers must approve the exact controller/comparator/worker sources and freeze criteria, separately prepare and review an ephemeral Linux x86_64 Python 3.11.18 runtime, record its selected source/package/scheduler module paths and hashes, and create a separate source/registration/environment-bound controller GO containing an exact worker GO. The runtime receipt covers selected APIs and module origins; it is not a whole-distribution or binary attestation.

Each worker runs in a fresh foreground OS process with a new session and process group. Commands use the registered interpreter with isolated Python flags. The import shim verifies selected actual imported module paths/hashes, rejects Noop checkpoint aliases, records its real PID/parent/session/group, then invokes the unchanged worker. All import, model setup, required compilation, allocations, propagation, replay, hashing, export and return costs remain inside the controller's launch-to-actual-wait wall interval. The worker's intended return field is never substituted for the observed OS exit. CPU deltas are taken across each reaped serial process family; cumulative child RSS peaks are retained without subtracting or adding nonconcurrent maxima. The controller itself still needs an external actual wait observation in a future caller.

Before each child, the controller rechecks the exact source and immutable admission hashes and reserves disk/memory headroom. A fixed per-file limit is installed in the child before numerical imports. Retained output sizes and live Linux process-group RSS are sampled against separate fixed caps. These checks are not a hard RSS or whole-filesystem allocation guarantee: between-sample peaks and overshoots are possible and remain failure evidence. Compiler/cache files outside the retained tree are not counted as retained output. The full console, actual worker peak RSS, compiler-child CPU/RSS, selected native allocation inventory, actual checkpoint capacity/copy counts and native attempt/replay counters remain distinct. Attempted or raised kernels receive no invented completed-step credit.

INT/TERM/HUP are forwarded to the assigned child group. Stop, cap violation or controller error ends later admission and kills only the known owned live child/group before an actual wait. There is no numerical timeout, retry, larger K or fallback. A failed resource observation cannot bypass known-child cleanup. An unexpected group or surviving descendant is reported conservatively as unknown work. Machine termination or an uncatchable controller kill can still prevent terminal receipts; immutable spawn/start prefixes then identify the last uncertain slot. No successful final state is inferred from such a prefix.

Every slot has immutable spawn, start, exit and validation receipts. `exit.json` records actual return/signal status, full external wall, bounded resource sample prefix/tail and commitment, CPU observations, and native event-prefix diagnostics. Failure leaves later slots unattempted. A missing or unreturned native event remains unknown work; a known zero count is not invented. Only all twenty-three normal actual exits, validated import identities and source/slot results admit independent comparison.

The comparator is authored separately and uses only the standard library. It checks the exact23 denominator, external exit/source/result/artifact bindings, source/primal/fixed-dual/time identities, native event chronology, copy/replay counters, bounded future manufactured NPZ arrays, endpoint masks, whole receiver and padded/physical gradients, edge-extension transpose, objective/gradient scalar consistency, and all registered finite differences. Every middle step is required; endpoint steps are retained without best-step selection. Comparison starts only after `terminal_children.json` is immutable. A failed numerical or resource gate cannot be turned into a successful controller report.

Fresh worker processes share the Devito/codepy compiled cache. The fixed saved→K2→K4 order can warm later variants. Native compiler console, generated C and available cache/library/timer metadata are preserved, but this pilot makes no fair-speed, matched-cost reconstruction, field-accuracy, independent-geology, new-checkpoint-method or student-final-interpretation claim. Its purpose is engineering derivative agreement and honest memory/work accounting.

Manufactured controls exercise real tiny dummy processes, signals, wait statuses, resource/receipt failures and cap overshoots, together with independent synthetic comparison/parser checks. They import no NumPy, Devito or PyRevolve and run no model, solver or project study. Resource probes used in portable dummy controls are explicitly labeled synthetic; they do not establish Linux RSS behavior. The held native runtime, source/criteria freeze, actual native execution and external controller wait remain future gates.
