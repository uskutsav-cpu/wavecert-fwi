The pinned Devito source and PyPI release JSON agree. This stage is a source/metadata design, not an installation route approved for execution. The frozen controller0a73, worker319 and protocol08 were preserved.

The METADATA text was obtained through its PEP658 sidecar,11,136bytes, SHA256099b9b6cad7ae7181e52d5ecf13c842b77ad017cdbf34a21b06e3f1bddcba5d0, matching the hash advertised in the release JSON. No wheel was downloaded. Therefore this is stronger evidence than a requirement inferred solely from a source checkout. PyPI JSON itself warns that uploaded release metadata can differ from distribution contents; the sidecar closes that particular gap for the selected wheel.

Root has requested preservation and a later separately versioned runtime correction, likely NumPy2.4.3 if its wheel and full closure are supported. This stage neither chooses that correction nor changes pins. Installing with --no-deps remains appropriate ONLY after a complete compatible hash-locked closure has been independently checked; it cannot make the current2.4.6 conflict valid. Patching METADATA, ignoring pip check, or silently substituting another Devito/NumPy version is excluded.

1. Before any cloud job, root must review a new compatible runtime contract, exact preparation source/workflow, source inputs, package/build lock and budgets. The current protocol cannot authorize a clean preparation success. A metadata-only resolver report can be retained as a failure without trying alternate versions.
