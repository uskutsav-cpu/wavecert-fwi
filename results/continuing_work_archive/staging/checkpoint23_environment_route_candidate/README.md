# Held environment-only route

This candidate prepares evidence for the reviewed checkpoint23 V2 runtime (NumPy2.4.3, SciPy1.17.1, Devito4.8.23, PyRevolve2.2.8, Python3.11.18). It cannot authorize checkpoint workers or PDE work. The c8f6 runtime bundle and all physics, source13 pins,23slots and criteria remain unchanged.

The workflow is staged here as `workflow_environment.yml`, not installed in the repository. The false registration runs only two fresh stdlib control processes. A separate root registration-only activation, directly following the reviewed source/control commit and attempt1, is required before setup-python or package preparation. The preparation GO is distinct from the native pilot GO. The final candidate environment receipt always has `native_use_review_clear:false`.

Preparation order is fixed: an actual Linux stdlib namespace/signal gate before packages; four exact URL/hash/capped sdists; static build-requirement inspection without imports; a wheel-only build closure under the shared runtime constraints; offline installation of that closure; one offline build of each registered source; final ordinary runtime resolution using exact successful built-wheel paths plus wheel-only other packages; a clean offline hash-locked install and pip check; source13 checks before the separately authorized import-only17-origin probe; closed-child evidence collection. No resolver sees an online sdist. Missing dependencies/backend/namespace support fail without repair, retries or fallback.

The source-build allowlist is exactly PyRevolve2.2.8, contexttimer0.3.3, cgen2025.1 and codepy2023.1. Only PyRevolve may produce a platform wheel. No Devito extras, MPI, GPU, compression or plotting dependency is requested. Build/import initializers execute native machine instructions and may probe CPU/compiler/cache. No Model/Grid/TimeFunction/Operator/Revolver is constructed by the route. The probe conservatively blocks observed forbidden Python calls and binds real classes and21 relevant callable implementations to pinned source; it does not claim a general sandbox or measure every native instruction.

The build wrapper uses a new network namespace, actual runner UID/GID, empty supplementary groups, no-new-privs and empty capability sets. Its first real Linux dummy must demonstrate namespace/privilege/network rejection, observed external signal and actual cleanup/wait before package work. Each source build repeats the namespace precondition check before exec. Local manufactured controls do not establish that Linux gate; it remains unexecuted.

The caller adapts frozen3f5 lifecycle functions: group ownership, deferred nonraising signal handlers through Popen handoff, actual waits and cleanup are retained. Added hooks provide DEVNULL stdin, bounded observation,1MiB console limit and preservation of known wait truth if final resource/receipt I/O fails. Logs are closed before copying; copied targets are hashed and compared. Unknown terminal/group state permits only explicit controller-owned prefix receipts, without stable child-log claims.

The small metadata artifact is separate from wheels. Pip/compiler temporary payloads are excluded. It contains all selected wheel/source hashes, full runtime/build dependency reports and locks, installed inventories, compiler/linkage hashes, actual17 origins, source/callable bindings and process receipts. Root can download metadata only. The wheel artifact retains the exact built/downloaded wheel bytes and build inputs; a later separately approved job must reinstall those same bytes rather than rebuild. This first exploratory resolution is not reproducible until its actual locks and wheel bytes are reviewed.

Caps are192MiB runtime wheels,64MiB build inputs,16MiB metadata and8GiB live task workspace, with4GiB disk headroom. The400MiB remote-artifact ceiling retains an unused128MiB interpreter-archive reserve; this implementation does not fetch that archive automatically. Actual retained artifacts are at most256MiB wheel/input payload plus16MiB metadata. Explicit downloads are size/hash/body bounded; pip resolver transfer bytes are not instrumented. Workspace/log sizes are observed and can overshoot between samples. These are not OS hard RSS or whole-filesystem guarantees.

Every subprocess has actual PID/group/wait/exit and whole launch-through-wait timing. Child CPU deltas and cumulative child peaks are labeled separately; nonconcurrent peaks are not added. Controller costs cover its measured interval through pre-finalization. Actual Action step/job wall must supply full startup/admission/finalization cost. No fair-speed or physics claim follows from preparation.

The first17-route-control attempt failed in six lifecycle cases because the copied header omitted `platform`; the helper and failure evidence are preserved. The corrected18 route controls pass, including signal handoff, actual0/7 exits, receipt/resource failures, artifact copying, transfer mismatch and admission rejection. The unchanged portable probe V2 suite passes25 separately. These43 controls use stdlib/dummy processes and synthetic files only. They do not install packages, run the actual namespace/import probe or validate a native environment.

Root and independent source review remain required before any publication or environment job. The actual closure, compiled scheduler, interpreter/system identities, Linux namespace behavior and actual17 imports remain unproved. Native use needs a later reviewed environment receipt and separate exact native GO. No package, install, actual import probe, PDE, cloud job, push or GO was executed by this staging task.

The staged `legacy_ci_branch_exclusion.yml` changes only the legacyCI push trigger to skip the dedicated environment branch. Without that guard, its existing verify-physics/evidence-study jobs would run alongside an environment-only push. Its job definitions and pull_request trigger are unchanged. Production/main workflows are untouched; root must review this orchestration-branch variant before publishing. The exact route manifest therefore binds15 source/workflow files.
